# Bloco 5: Git colaborativo, code review e CI

**Semana 5 · cerca de 5 horas**

## Objetivo

Trabalhar como em um time: pull requests com boas descrições, revisão de código dada e recebida, CI rodando os testes a cada mudança e comunicação técnica escrita com clareza.

## Como dividir a semana

- **2h de estudo:** os materiais abaixo, na ordem.
- **2h de prática:** os exercícios, **sem IA escrevendo código**. Se travar, use a IA só para explicar o conceito ou o erro.
- **1h de fechamento:** preencher o `resumo.md` e fazer a `avaliacao.md`.

Se não der tempo de terminar, continue na semana seguinte no mesmo ritmo. Nunca compense dobrando as horas.

## O que estudar (nesta ordem)

1. **Pro Git** (git-scm.com/book, em português), capítulo 3 (branches) e capítulo 5 (Git distribuído).
2. **GitHub Docs**: "About pull requests" e "Quickstart for GitHub Actions".
3. **Google Engineering Practices** (google.github.io/eng-practices): "How to do a code review" e "The CL author's guide". É o guia de code review do Google, gratuito.

## Prática

1. Configure um GitHub Actions que rode os testes do projeto a cada push e pull request. Leva cerca de 1 hora.
2. Quebre um teste de propósito, abra um PR e veja o CI bloquear.
3. A partir de agora, toda mudança no projeto entra por PR, com uma descrição de três partes: o quê, por quê e como testar.
4. Faça um self-review de um PR seu antes de pedir revisão. Depois, peça a um colega para revisar.
5. Revise um PR de outra pessoa (de um colega ou de um projeto open source pequeno) e deixe três comentários construtivos.

## Regra da semana

Nenhuma linha de código entra no projeto se você não conseguir explicá-la em voz alta.
